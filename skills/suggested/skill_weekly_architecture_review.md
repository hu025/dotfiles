# 每周架构审查流程 — Weekly Architecture Review

## 何时使用
每周一，或收到用户指令"做架构审查"。

## 六大维度审查

### 1. 模型层
- 当前模型表现如何？有无明显缺陷？
- 是否有更优模型可供切换？
- MiniMax / NVIDIA NIM / 本地模型各自表现对比

### 2. 记忆层
- 记忆库总大小，有无 30 天+ 未使用的条目？
- 有无矛盾信息需要解决？
- 用户偏好是否有新变化需要写入？

### 3. 技能层
- 现有技能中有无过时/错误/可合并的？
- 用户重复请求的领域是否已有技能覆盖？
- 有无新的高效工具/框架可以封装为技能？

### 4. 工具层
- Python 依赖是否有过时/安全漏洞？
- 系统工具有无更好替代（e.g. ripgrep → grep, fd → find）？
- 有无可封装的重复操作？

### 5. 浏览器自动化
- 现有 browser 脚本是否稳定？
- 有无新的网页结构需要适配？
- 能否将更多手动浏览任务自动化？

### 6. 自主改进
- 本周成功率/失败率趋势
- 有无反复失败需要系统性解决？
- 最应该优先改进的 1-3 个点是什么？

## 输出格式
生成周报到 `~/.hermes/self-improvement/reports/weekly/weekly_YYYY-MM-DD.md`
并向用户简洁汇报下周优先计划。
