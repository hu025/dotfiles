## 陷阱1：初稿复用前一章内容（2026-07-31）

**现象**：创作第112章时，第一稿不自觉复用了第111章的场景和文字（林念幻象回闪、冰壁描写、对话几乎一字不差）。

**根因**：读前一章了解衔接点时，记忆被前一章的完整场景锚定，写新章时下意识沿用了相同的情绪和场景框架。

**解法（强制执行）**：
1. 读上一章 → 只抓**剧情节点**（谁死了/谁说了什么话/什么决定），**不抄任何场景描写和对话**
2. 新章开写前，先在 execute_code 里做"原创性预检"：
   ```python
   # 扫描新章前200字是否重复上一章开头
   prev = open(f"第{n-1}章.txt").read()[:200]
   new  = open(f"第{n}章.txt").read()[:200]
   overlap = len(set(prev) & set(new))  # 字符级重叠检测
   ```
3. 如果新章开头和上一章有**相同场景**（都在医疗室醒来、都描写同一物件），立刻重写

**验证方法**：grep 新章中是否出现上一章的标志性句子或描写段落。

## 陷阱2：批量替换 em-dash 后双逗号问题（2026-07-31）

**现象**：用 `content.replace('\u2014', '，')` 批量替换所有 em dash（—）为中文逗号后，产生大量 `，，`（双逗号）序列。

**根因**：原文多处已是 `严重——那次` → `严重，那次` OK；但原文是 `严重，那次`（已有逗号）+ em dash → `严重，，那次`（双逗号）。

**正确做法（单次 execute_code 完成）**：
```python
content = content.replace('\u2014', '，').replace('\u2013', '，')
content = re.sub(r'，，', '，', content)  # 同一 code block 清理双逗号
```
不能分两个 execute_code 调用——第二个调用会找不到第一个的字符串状态（文件句柄已关闭）。

**验证**：`content.count('，，')` 必须为 0。

## 陷阱3：章节删除后 CHARACTERS.md 状态未同步

**现象**：删除第112-116章后，CHARACTERS.md 里记录"血祖已死（第116章）、林念已死亡（第116章）"与正文不符。

**解法**：删除章节时，**同时更新**三处设定文档：
- `CHARACTERS.md` — 角色状态恢复至上章
- `PLOT_POINTS.md` — 该章节剧情标记为删除/待重写
- `progress.json` — 章节数回退

## 陷阱4：PLOT_POINTS.md 中的倒计时残留

**现象**：章节删除后，PLOT_POINTS 里仍记录原定剧情（如"第113-116章决战血祖"），但正文已清空，倒计时数字也会过时。

**解法**：每次删除章节后，在 PLOT_POINTS 对应条目标注 `⚠️ 已删除，待重写`，不要留空白行导致结构断裂。
