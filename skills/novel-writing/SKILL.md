## 第一技法：开篇钩子

**前20%决定生死。** 读者在前20%决定是否继续。

### 十种强力开头

| 类型 | 示例 | 效果 |
|------|------|------|
| 行动切入 | "子弹擦过耳边，击碎花瓶。他没回头，翻滚躲到沙发后。" | 即时紧张 |
| 反常情境 | "死人坐在办公桌前，正在写一份报告。" | 激发好奇 |
| 震撼对话 | "「我把孩子卖了。」妻子平静地说。" | 情感冲击 |
| 倒计时 | "还剩72小时。倒计时从现在开始。" | 压迫感 |
| 触感切入 | "胸口像被一只手攥紧。他喘不上气。" | 身体共鸣 |
| 断裂句 | "他做了一个决定。这个决定会让他后悔——" | 悬念截断 |
| 数字冲击 | "七阶吸血鬼，不是她朋友。" | 信息冲击 |
| 画面定格 | "血从门缝里渗进来，在他脚边汇成一小滩。" | 视觉冲击 |
| 感官入侵 | "腐烂的甜腥味钻进鼻腔，他干呕了一下。" | 生理反应 |
| 冲突瞬间 | "「滚。」他说。这个字掉在地上，砸出回响。" | 对抗张力 |

### 绝对禁止

- 背景介绍 / 人物出场白 / 无关铺垫 / 慢热
- "那天天气晴朗" / "先介绍一下这个世界"
- 回顾上章 / 日常流水账

**开篇第一个字就要让读者停不下来。**

## 第二技法：代入感

全程锁定主角视角。每一个感官、情绪、念头都是叙事核心。

**核心技法：**
1. **身体先行** — 先写身体反应，再写心理活动
2. **触感细节** — 手心汗/脚心凉/肋骨上的手指
3. **情绪画面** — 把抽象情绪写成具体触感

**禁止：**
- 上帝视角旁观叙事
- 角色割裂（前后性格不一致）
- 跳戏/脱节

## 第三技法：文笔打磨

### 换词指南

| 禁用词 | 替换 |
|--------|------|
| 觉得 | 知道/明白/意识/感受 |
| 看到 | 看见/瞅见/目光落在 |
| 走 | 蹭/挪/踏/踩/迈 |
| 说 | 吐出/挤出/吐出字来 |
| 然后 | 之后/接着（句中）/删掉（句首） |
| 其实 | 实际上（句中） |
| 竟然 | 居然/哪来 |
| 逐渐 | 慢慢/一点一点 |
| 众多 | 很多/不少/一群 |
| 面对 | 碰上/撞上 |

### 触感意象库

- 潮汐礁石 — 被反复冲刷，外表不动，内里减少
- 暴风雨里的鸟 — 羽毛湿的，还没抖干净
- 手指在肋骨上 — 一根一根数，数到某根停住
- 温水里的冰 — 裂开，但没有声音
- 没有底的井 — 眼窝深得像两口没有底的井

### 节奏

- **短句**：制造停顿，制造重量 — "腿在发抖。""但没有回头。"
- **长句**：制造绵延，制造窒息 — "他盯着那个数字看了三秒，四秒，五秒，在这个沉默里他听见了很远的东西——不是距离上的远，是时间上的远。"
- **段落**：不均匀分布，有的一整段，有的就一行

## 第五技法：悬念反转

### 悬念类型

- **钩子悬念** — 问一个问题，不回答
- **恐惧悬念** — 知道危险要来，但不知道什么时候来
- **秘密悬念** — 读者知道但角色不知道，或反过来

### 反转原则

意外但合理：
- 不能为了反转而反转
- 反转要重新定义前面所有细节
- 最好的反转是回头重看才发现伏笔早埋好了

### 章尾钩子

每章结尾必须有**高能钩子**：
- 抛出问题 / 揭示真相的一角 / 在动作最高点截断

## 第六技法：质量终检（强制去AI化）

**创作即检测。** 每章完成后必须通过本技法全部检查项，才能进入文档同步。

---

### 一、词汇过滤（必过三关）

**判断原则：**
- **叙述语/旁白/内心独白 → 必须改**
- **对话 → 保留（人类口语）**
- **时间顺序动作链（主语同+动作连续）→ 保留**

#### 关卡1：原有禁用词

| 禁用词 | 判断 | 替换 |
|--------|------|------|
| 仿佛 | 叙述语禁用 | 像/如同/就好像 |
| 逐渐 | 叙述语禁用 | 慢慢/一点一点 |
| 然后 | 句首禁用 | 之后/接着 |
| 其实 | 句首禁用 | 实际上 |
| 竟然 | 叙述语禁用 | 居然/哪来 |

#### 关卡2：AI高频Tells（发现即改）

| 禁止词/词组 | 替换方案 |
|-------------|---------|
| 深入（地） | 细细/认真/仔细 |
| 彰显 | 体现/显示/说明 |
| 不可或缺 | 必不可少/必须有 |
| 不可或缺地 | 必不可少的 |
| 日益 | 越来越/一天比一天 |
| 显著 | 明显/很大/突出 |
| 逐步 | 一点点/慢慢/渐渐 |
| 持续 | 一直/不停/（注意：和"不断"互换无效！见陷阱说明） |
| 不断 | 一直/不停/（注意：和"持续"互换无效！见陷阱说明） |
| 极为 | 特别/非常/十分 |
| 极其 | 特别/非常 |
| 尤为 | 特别/尤其 |
| 相当 | 很/挺/颇 |
| 颇为 | 很/挺 |
| 而言 | 说来/来看 |
| 确保 | 保证/让/使 |
| 旨在 | 目的是/是为了/致力于 |
| 有助于 | 能/可以/帮助 |
| 得以 | 能够/终于 |
| 随着 | 跟着/顺着 |

#### 陷阱：关卡2词组互换代无效

**"持续"↔"不断"互换无效**——两者都在禁用列表，互换等于换汤不换药。
- ❌ "不断向外扩散" → "持续向外扩张"（仍然FAIL）
- ✅ "像是封印的边界在缓缓扩张"（彻底改写意象）

**"深入"↔"持续"也不是安全替换**——"深入"禁用但"持续"也在禁用列表，改了也白改。
- ✅ 直接改句子结构，不在禁用列表内换词

**安全策略**：遇到关卡2词卡住时，不要在禁用列表里找同义词替换，而是用**完全不同的句子结构或意象**来表达同样的意思。

#### 关卡3：AI固定句式（整句重写）

**段落开头禁用句式（直接删或改写）：**
- "在这一刻……"
- "不得不说……"
- "值得注意的是……"
- "从这个角度来看……"
- "正因如此……"
- "正是在这种背景下……"

**转折句禁用模式：**
- "然而……" → 改为"但……"或"可……"或直接删
- "尽管如此……" → 改为"但……"
- "与此同时……" → 改为"这时候……"或"就在这会儿……"

### 二、结构检查（机械验证）

> 以下每项必须逐项确认，不能靠感觉。

1. **段落长度**：是否有1句段落？是否有6+句段落？两者都有才合格。
2. **句子长度**：是否有5字以下短句？是否有35字+长句？两者都有才合格。
3. **破折号检查**：全文 em dash（—）和 en dash（–）必须替换为单 hyphen（-）。**零容忍。**
   ```bash
   # 检测破折号（显示具体位置）
   grep -n $'\u2014\|\u2013' chapters/第X章.txt
   ```
4. **三连句检测**：全文不能有超过2个连续结构完全相同的短句（3个"他XX，他XX，他XX"连续出现 = 违规）。
5. **列表检测**：不能出现"首先/其次/最后"三段式列表（小说不是说明书）。
6. **Tricolon检测**：每1000字内不超过1个"X、Y、Z"三连排比句。

---

### 三、爽点与正文一致性检查

> **第109章教训**：爽点写"击杀血祖"但正文只杀分身。血祖真身未死，爽点严重失实。

每章写完，对照爽点条目逐条 grep 正文验证：

| 爽点类型 | 验证方法 |
|---------|---------|
| 击杀/击败 | `grep -n '击杀\|杀死\|斩杀\|抹杀' chapters/第X章.txt` |
| 获得物品/能力 | grep 正文确认到手 |
| 揭示真相/秘密 | grep 正文确认真相揭露 |
| 突破境界 | grep 正文确认突破 |
| 关系变化 | grep 正文确认实际变化 |

**爽点条目必须100%有正文对应。爽点写"击杀"但正文只打伤/击退 = 修改爽点注释。**

---

### 四、章节衔接+倒计时一致性检查

> **第107章爽点"剩余3天"→第109章爽点"剩余2天击杀血祖"——但第109章正文只杀分身，血祖未死。倒计时与剧情实际进度脱钩。

每章结束时检查：
1. **倒计时剩余时间与本章实际消耗是否一致**（上章剩X天，本章做了什么，结尾应为X-1天）
2. **倒计时对象是否还存活**（击杀目标死亡后倒计时不能继续）
3. **爽点击杀记录与正文一致**

```bash
# 验证本章击杀记录
grep -n '击杀\|杀死\|斩杀' chapters/第X章.txt
# 验证倒计时
grep -n '倒计时\|剩余.*天' chapters/第X章.txt
```

### 五、人类触感检查

- [ ] 有没有一个**具体的身体触感**？（手心汗/肋骨发紧/膝盖发软）
- [ ] 有没有一个**只有这里才能用**的细节？
- [ ] 有没有一个情绪是**"说不出来"**的，只能用身体表达？
- [ ] 有没有一处**"没说完就断了"**的句子？
- [ ] 是否有**具体数字/名字/日期**（AI只会写"几天后"，人会写"星期三"）
- [ ] 是否有**作者立场**（喜欢/讨厌/害怕）而不是中立叙事？
- [ ] 是否有过**口语/方言/粗口**（视风格而定，让角色更像人）

### 六、机械化执行流程

每次写作完成后，**按顺序**执行：

```
Step 1: 搜索 em/en dash → 全部替换为 hyphen（机械操作）
Step 2: 扫描关卡1+关卡2 禁用词 → 逐句重写
Step 3: 扫描关卡3固定句式 → 删或重写
Step 4: 运行审计脚本验证：
   python3 ~/.hermes/skills/pharaoh-write/skills/anti-ai-filter/scripts/novel-chapter-ai-audit.py <章节文件>
   → 全部 PASS 才能继续，有 FAIL 就重写对应段落

Step 4b（必须执行，审计脚本有漏扫）：运行精确 grep 补扫：
   ```
   # 补扫句首"然后"（审计脚本会漏扫）
   grep -n '^[\s]*然后' <章节文件>
   # 补扫AI高频词（审计脚本不覆盖）
   grep -n '再次' <章节文件> | grep -v '又一次'
   # 补扫 Tricolon（审计脚本字符串匹配不精确）
   grep -nP '^[^，,\n]{2,30}[、][^，,\n]{2,30}[、][^，,\n]{2,30}[，。]?$' <章节文件>
   ```
   ⚠️ **教训**：第63章审计脚本初扫4处，实际还有4处「然后」漏扫。全量验证必须同时跑脚本+grep，两次全绿才算完成。
Step 5: grep 验证爽点与正文一致性
Step 6: grep 验证倒计时一致性
Step 7: 完成人类触感检查清单
```

**全部通过才能进入文档同步阶段。任何一项未过，重写相关段落。**

> **⚠️ 不要靠感觉。** 必须调用审计脚本验证，只有人说"我检查过了"不够——脚本必须 exit 0。

## 创作流程（续写/新项目）

### 写作前

1. 确定项目 → 读取对应设定文档（末日 `story/` / 高武 `.learnings/`）
2. 读取 `STORY_BIBLE.md` — 世界观和当前阶段
3. 读取 `CHARACTERS.md` — 角色状态
4. 读取 `PLOT_POINTS.md` — 剧情进度和待解决问题
5. 读取 `ERRORS.md` — 已知问题
6. 读取 `outline.md` — 本章在大纲中的位置
7. 读取上一章 — 了解剧情衔接点

### 写作中

1. 开篇第一句用**第一技法**（十种开头之一）
2. 全程用**第二技法**锁定代入感
3. 用**第三技法**打磨每句用词
4. 用**第四技法**处理情绪场景
5. 用**第五技法**编排悬念反转
6. 每写500字自检：代入感是否丢失？节奏是否疲软？

### 写作后

1. **第六技法**去AI化检查（六步执行完毕才能继续）
2. 知识边界检查
3. 章节质量审计
4. **同步文档（一次性完成）：**
   - `CHARACTERS.md` — 角色生死、境界、关系变化
   - `PLOT_POINTS.md` — 本章摘要+下章方向+待解决问题
   - `ERRORS.md` — 解决/发现的问题打勾或登记
   - 本章文件（末日 `.txt` / 高武 `.md`）
   - `progress.json` — 更新章节数和字数

## 关键陷阱提醒

1. **验证文件存在**：摘要说某章已写完 → 必须 `ls chapters/` 确认
2. **高武重生格式**：`chapters/第58章_标题.md`（下划线，`.md`）
3. **末日一小时格式**：`chapters/第109章.txt`（无下划线，`.txt`）
4. **进度文件校验**：每次任务前检查 `progress.json` 与实际章节数是否一致
5. **子代理结论必须自验**：delegation分析fiction后，必须 grep/读文件 核实每一处报告
6. **倒计时悬念必须标注剩余时间**：每章结束时检查未回收的倒计时
7. **角色生死以章末爽点摘要为准**：正文叙事动词（逃/跑/消失）不可靠
8. **高武重生无 `story/` 目录**：设定文档全在 `.learnings/` 下
8. **爽点注释必须与正文一致**（⚠️ 本次教训）：爽点写"击杀X"时，必须 grep 正文确认真的击杀了。只打伤/击退/杀分身的，不能写"击杀"。倒计时同理——目标死亡后倒计时自动作废，不能继续递减。
9. **⚠️ 任务优先原则**：用户明确要求「发给我第X章」= 检索交付任务，**不要**用续写任务覆盖。必须先确认目标章节文件存在（ls+wc验证），再发送。
9. **⚠️ 项目区分陷阱（本次教训）**：「顿悟系统第58章」= 高武重生，「末日一小时第X章」= 末日一小时。两部小说独立。项目判断方法：先读 `progress.json` 确认实际章节数，再确认文件格式（末日 `.txt` / 高武 `.md`）。**绝对不要**看到续写任务就沿用当前工作目录的末日一小时项目。

10. **⚠️ 初稿复用前一章内容陷阱（本次教训）**：写第N章时读前一章了解衔接点，不自觉复用了上一章的场景/对话/描写（2026-07-31第112章第一稿几乎照搬第111章）。解法：读前一章只抓剧情节点（谁死了/谁说了什么/什么决定），**不抄任何场景描写和对话**。写新章前用 execute_code 做字符级原创性预检。

11. **⚠️ em-dash 批量替换双逗号陷阱（本次教训）**：用 `replace('\u2014', '，')` 批量替换 em dash 后，如果原文某处已有逗号紧邻 em dash（如 `严重，那次——`），会产生 `，，`。正确做法：**同一 execute_code code block 内**，先批量替换 em dash，再用 `re.sub(r'，，', '，', content)` 清理双逗号，两步连贯执行不分两次调用。验证：`content.count('，，')` 必须为 0。

12. **⚠️ 章节删除后三文档同步**：删除章节时，必须**同时**更新 CHARACTERS.md（角色状态恢复至上章）、PLOT_POINTS.md（该章标记⚠️已删除待重写）、progress.json（章节数回退）。只删章节文件而不同步三文档，会导致设定文档与正文严重脱钩（2026-07-31：删112-116章但CHARACTERS.md仍记"血祖第116章已死"）。
7. **⚠️ 审计脚本可能报错退出**：脚本最后 `KeyError: 'count'` 是正常的（脚本本身有小bug），看前15行 `PASS/FAIL` 统计即可判断是否通过。所有 `PASS` 则章节合格。
8. **⚠️ Tricolon修复策略**：Tricolon（X、Y、Z三连排比）是AI高频Tell。"取决于A、B、C"这类句式触发审计。修复方向：①拆成两句（"A和B有关，C也有影响"）②用"比如A、B、C"替代③直接一句话概括而不列举。最安全的是直接删除列举，比如"弟子修炼效率受很多因素影响。"一行解决。
9. **⚠️ sed全局替换em dash的风险（本次教训）**：用 `sed -i 's/——/-/g'` 一次性替换 em dash 时，会误伤原本正确的单 hyphen——比如 "一看——身侧" 替换后变成 "一看-身侧"，但 "濒临除名" 也含 em dash 字符会被误改。更稳妥的做法是：先 grep 找出所有 em dash 位置，逐一判断是否需要替换，或者直接 patch 特定位置而非全局替换。
10. **⚠️ sed + patch 交替执行的副作用**：同一文件上先 sed 后 patch，sed 已经改过的部分 patch 可能找不到原始字符串。解决方案：每轮操作后立刻 grep 验证状态，不要跨轮累积替换。
11. **⚠️ 审计脚本 `KeyError: 'count'` 是假性报错**：脚本最后一行 `count = result["count"]` 有 bug，exit 1 但所有 PASS 检查仍有效。以 `PASS/FAIL` 统计行数为准，脚本错误行可以忽略。
12. **⚠️ 固定句式"最后"替换的完整句式改写陷阱**：审计脚本对"最后"子串匹配（AI_PHRASES列表含`"最后"`），合法用法"最后一步""第三块最后动手""留到最后"均被误杀。
    - ❌ "这是最后一步" → "这是收尾一步"（"最后"仍在）
    - ❌ "第三块留到最后" → "第三块留到收尾"（仍含"最后"）
    - ❌ "最后说一遍" → "末了说一遍"（审计脚本也命中末/尾变体）
    - ✅ "但这是收尾一步"（删掉"最后"）
    - ✅ "第三块，等其他都拿完了再动手"（彻底改写句子）
    - ✅ "在那场决定性战斗中"（替换整个分句）
    - 根本原则：**不要改"最后"为其他词，要删掉"最后"这个词，或用完全不同的句子结构**
13. **⚠️ "戛然而止"含"然而"导致误判**："戛然而止"是常用成语，但包含子串"然而"，会被AI_PHRASES规则命中。审计脚本匹配的是子串而非完整词。修复：完全避免这个成语，改用"戛然而""声音断了""讲述停住了"等替代表达。
14. **⚠️ "再次""闪烁"组合触发AI高频词**：审计脚本的AI_PHRASES列表中有"再次"。常见组合"系统光幕再次闪烁""灵光再次涌现"等都会被命中。修复：用"闪了一下""亮了一瞬""又闪了一下"替代。
15. **⚠️ Tricolon判断要区分来源**：审计脚本的Tricolon检测是纯字符串匹配，会误判父亲的原话。比如"三百年的思念、三百年的委屈、三百年的痛苦"——这是父亲的情感独白，是authentic voice，不应删除。**判断标准：角色在说话/写信/回忆时用的三连是合法表达；纯旁白/叙述枚举才是AI堆砌。**

16. **⚠️ Tricolon修复策略**：Tricolon（X、Y、Z三连排比）是AI高频Tell。修复方向：
    - ①拆成两句：列表行不以句号结尾，让列表和解释分家
    - ②改动态描写：将"龙魂、凤魂、麒麟、玄武"四连名词改为"四道光芒交织"的动态动作
    - ③直接删除列举：比如"弟子修炼受很多因素影响"（比枚举A、B、C更自然）
    - ④合并为一句主语："四块碎片同时爆发，龙魂、凤魂、麒麟、玄武四族之力汇于一处"
    - 最安全的是改动态动作，让静态枚举变成场景流动。

17. **⚠️ "最后"替换的完整句式改写**：审计脚本对"最后"+标点+动词短语均报FAIL。只改"最后"本身无效——要改整个句子的结尾结构。
    - ✅ "三百年的坚守，三百年的等待。最终，换来的是燃尽灵魂"（改为"最终"）
    - ✅ "父亲的声音，就此断了"（直接删除"最后，换来的是"整个分句）
    - ⚠️ 不要改"最后"为"末了"——审计脚本也会命中末/尾的变体
    - 根本原则：让句子以不同结构结尾，或直接删掉整个"最后X了"分句

16. **⚠️ em-dash高频热点章节（2026-07-02更新）**：实测发现《高武重生》第52-59章才是重灾区（共658处），第1-51章已清理。执行em-dash批量清理前应先 `execute_code` 扫描全文确定热点，不要假设前半部分最严重。热点分布：第58章124处/第59章116处/第55章92处/第56章80处/第52-54章各70-76处。

## 创作宪章（刚性标准）

章章达标、缺一不可：

1. **极致文笔** — 用词精准、语句凝练、文风统一高级，无口水无废话无俗套
2. **超强沉浸** — 全程主角视角，心理/感官/情绪细腻刻画，零上帝视角
3. **精准切入** — 零无效铺垫，开篇即冲突/悬念/危机/名场面，开篇即高光
4. **持续吸引** — 张弛节奏+伏笔悬念反转贯穿，章尾高能钩子
5. **技法创作** — 六大技法同步运用，禁止流水无脑创作

底线规范：人设不崩 / 剧情自洽 / 视角稳定 / 无水字数 / 情绪张力到位

## 系统性全书画框审查流程（2026-07-01）

执行全书画框审查时，按以下步骤执行：

### Step 1：建立基线
```
1. 读取 progress.json 确认章节数
2. ls chapters/ 确认文件存在+格式正确
3. 读取 .learnings/STORY_BIBLE.md / CHARACTERS.md / PLOT_POINTS.md
```

### Step 2：逐章扫描关键要素
用 execute_code 批量扫描：
- 人物出场标记（grep 各角色名）
- 父母姓名一致性（grep 林天豪/林渊）
- 关键剧情节点（陈霖死亡/复活/净化/结局、黑袍首领揭露）
- em-dash热点（统计每章em dash数量）
- 章节衔接（检查TBC标记状态）

### Step 3：分类定级
```
P0级：逻辑断裂/致命矛盾（父亲名字不一致、boss身份未揭露）
P1级：剧情重大不完整（角色消失10+章无交代、力量体系崩溃）
P2级：体验细节问题（em dash过度使用、次要角色去向不明）
```

### Step 4：优先修复P0
### 完本后审查清单

完成最终章后，执行以下检查：

**⚠️ 章节修改范围约束（必须第一时间确认）**
- 用户可能有范围限制（如"只能动61-65章"、"只能处理第111章"）。修复前必须明确范围。
- **⚠️ subagent 问题归因不实**：审查报告中的 P0/P1 问题不一定在目标章节内部。必须读取章节全文 + grep 关键字验证后，才能确认真正需要修改的内容。审查报告说"第X章有Y问题"，但该章正文从未出现相关文字——此类误报必须逐项核实后才能执行修改。
- 当P0问题涉及前文时，在允许范围内给出**替代解释**而非修改前文
- 替代解释原则：无法改前文名字→在结局章补充"化名"说明；无法改前文设定→在结局章补充"融合/升华"

**P0 剧情逻辑检查（任何完本都必须做）：**
- [ ] **书名核心卖点不消失**：扫描高潮章节（终局前5章+结局章），确认书名中的核心机制（系统/能力/设定）有明确交代
- [ ] **所有承诺的威胁/伏笔必须回收**：反派说"X将复活"，结局章必须兑现或明确说明其命运（哪怕一句"已被消灭"）
- [ ] **跨章人名/设定一致性**：同一角色全书用同一名字，boss身份终局章必须直接揭露
- [ ] **主角核心能力不消失**：最强手段在中后期消失超过5章无解释属P0级

**P1 剧情完整性检查：**
- [ ] **关键角色消失有交代**：角色在某章突然不见，下章必须补充说明（去哪儿了/为何不在）
- [ ] **重要NPC有独立场景**：父母/配偶等核心NPC须有至少1个独立场景（不是只在别人对话里被提）
- [ ] **反派团体有具体清算**：被灭门/处刑等须有具体人物/场景，不能一句"被清算"带过

**em-dash 大清理（完本后强制执行）：**
- [ ] 用 execute_code 扫描全文 em-dash 数量：`c.count('\u2014') + c.count('\u2013')`
- [ ] 超过阈值（>0）则批量替换为中文逗号 `，`：`new_line.replace('\u2014', '，')`
- [ ] 重点清理：章节衔接处、对话中、对白列表
- [ ] 验证：清理后 grep 全文确认零残留

**修复范围原则：**
- 优先修复61-65章（最新章节），不动前46章
- 如问题涉及前46章，在审查报告中标注为"需手动修复"
- P0问题必须先修复再交付，修复方案写入审查报告
