# WeChat/Weixin Media Upload: ret=-1 Diagnosis

## The Problem

All media sends (images, documents, voice) via WeChat iLink API fail with:
```
getUploadUrl returned neither upload_param nor upload_full_url: {'ret': -1}
```

Text sends (`send_weixin_direct(media_files=[])`) still work. Only media upload is blocked.

## Root Cause

WeChat iLink platform API (`/ilink/bot/getuploadurl`) returns `ret: -1` at the **WeChat server level** — not a token, auth, or config problem. The HTTP request succeeds (200 OK) but WeChat returns a business-level failure code.

**Primary cause**: WeChat bot accounts on personal WeChat have **restricted or no media upload capability** via the iLink API. This is a platform-side permission issue, not a configuration one.

**Secondary causes** (these cause token/session errors, not `ret: -1`):
- iLink service degradation → check https://status.weixin.qq.com/
- Companion App killed → causes `errcode=-14 session timeout` (different error)

## What Does NOT Fix It

- Re-scanning QR code (token is not the issue)
- Changing image format, size, or quality
- Restarting the gateway
- Different `media_files` tuple formats
- OpenClaw (uses the same iLink API → same failure)
- QQ (does not support MEDIA attachments at all)

## Diagnostic Commands

```bash
# Confirm gateway running
systemctl --user status hermes-gateway.service

# Check all recent upload errors
tail -50 ~/.hermes/logs/gateway.log | grep -E "ret.*-1|getUploadUrl|send_document"

# Try text-only send to confirm channel is alive
# (text sends work even when media is blocked)
grep WEIXIN_TOKEN ~/.hermes/.env
```

## User-Facing Workaround

When a user needs an image urgently and WeChat media upload is blocked:

1. **Direct them to the local file path** — images generated by Hermes are stored at:
   ```
   /home/saber/.hermes/cache/images/<filename.jpg>
   ```
2. **Send the path as text** and let them open it manually
3. **No programmatic workaround** — the block is at the WeChat API level, not code level
